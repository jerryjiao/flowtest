## 3. KnowFlow recall quality for planning

Workspace initialized at `flowtest/kb` (knowflow 0.5.0), seeded with two
notes (demo-site product notes; a real lesson from the executor run:
`not_text` is a *visibility* assertion, hidden DOM nodes false-fail naive
checks). Synthesized per the KnowFlow agent contract; `knowflow health`
green.

| Query style | Result |
|---|---|
| `knowflow query` (semantic) | unavailable without an embedding API key (`ZHIPUAI_API_KEY`) — gated, not broken |
| keyword, single term (`checkbox`, `not_text`, `isChecked`) | exact hit, right page |
| keyword, distinctive compound (`Invalid credentials`, `reset demo data`) | exact hit |
| keyword, long phrase (`task list checkbox`) | miss — grep is literal |

**Verdict: usable, not magic — KB stays optional.** Recall is reliable when
the agent does what [flowtest-kb](../../skills/flowtest-kb/SKILL.md) already
prescribes (2–4 short keyword queries, not one long one), on a corpus the
size of a lessons file. Semantic search is an opt-in upgrade for users who
configure a key, never a prerequisite. This matches ADR-0001's stance and
the engine's degraded-Learn fallback (`flowtest/lessons/`).
